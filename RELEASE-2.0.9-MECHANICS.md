# RaidRU 2.0.9 — Mechanics Analysis

## Цель

Сделать вкладку **Разбор** сопоставимой по полезности с полным Browser Replay JSON, не загружая заново десятки тысяч координатных/дружеских событий.

## Архитектура

Данные боя теперь разделены на два независимых слоя:

1. **Replay Core** — карта, игроки, позиции и базовые касты. Загружается текущим `/wcl/exact-replay` и хорошо кэшируется.
2. **Mechanics Pack** — отдельный `/wcl/mechanics`: hostile casts, hostile debuffs, hostile summons и deaths. `includeResources` здесь не используется.

Один клик **«Загрузить механики»** делает максимум один GraphQL-запрос WCL. Если одна из категорий имеет `nextPageTimestamp`, Worker сохраняет курсоры и возвращает HTTP 206. Следующий клик **«Догрузить»** продолжает только незавершённые категории. Готовый pack хранится в Cloudflare cache 30 дней для завершённых боёв.

## UI

В `WCL → Разбор` появились:

- кнопка `⚡ Загрузить механики`;
- подробный фактический таймлайн с дорожками `Касты босса / Дебаффы / Адды / Смерти / Движение`;
- группировка по spell ID;
- количество применений и тип механики;
- медианный интервал повторений;
- количество целей для дебаффов;
- корреляция каждого применения с фактическим движением/разбросом рейда;
- переход на нужное время Replay одним кликом;
- фильтры категорий;
- `✦ Создать план из механик` — создаёт ограниченное число сцен, но переносит подробный WCL timeline в редактор.

Если загружен старый полный `raidru-wcl-replay-browser v2` JSON, Mechanics Analysis строится **локально из его timeline** и не обращается к WCL API.

## Rate-limit policy

- нет автопагинации;
- один пользовательский клик = максимум один WCL GraphQL request;
- реальный HTTP 429 соблюдается без retry-loop;
- Replay Core остаётся доступен даже если Mechanics Pack ещё не получен;
- готовый pack повторно берётся из серверного cache.
