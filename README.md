# RaidRU

Русскоязычный визуальный планировщик рейдов World of Warcraft с импортом тактик из RaidPlan.

**Текущая версия:** `0.8.35`  
**Сайт:** https://natalikh.github.io/raidru/

## Что это

RaidRU — planner-first инструмент для подготовки рейдовых сцен: позиции игроков и мобов, маркеры, зоны, линии и стрелки, заметки, таймлайн и отдельные планы под разные сложности.

Основная цель проекта — дать русскоязычной рейдовой группе простой способ перенести существующую схему из RaidPlan, доработать её в RaidRU и использовать как самостоятельную тактическую карту.

## Основные возможности

- визуальный редактор рейдовых сцен;
- отдельные планы для **Обычного / Героического / Эпохального** режима;
- отдельные вкладки **RaidRU** и **RaidPlan**;
- импорт RaidPlan по обычной ссылке на план;
- перенос позиций, текста, ролей, рейдовых маркеров, мобов, зон, линий и стрелок;
- сохранение оригинального фонового изображения арены RaidPlan;
- фильтрация скрытых и служебных объектов RaidPlan;
- маршруты и траектории движения;
- таймлайн сцен;
- состав рейда и роли;
- заметки и глоссарий;
- локальное сохранение данных в браузере;
- импорт/экспорт стратегии;
- экспериментальный локальный Warcraft Logs Replay.

## RaidPlan import

Импорт устроен так:

```text
RaidPlan URL
    ↓
RaidRU
    ↓
Cloudflare Worker /raidplan
    ↓
userdata.raidplan.io
    ↓
RaidPlan JSON v2
    ↓
raidplan-importer.js
    ↓
отдельная вкладка RaidPlan выбранной сложности
```

Импортированный RaidPlan не заменяет основной набор сцен RaidRU и сохраняется отдельно для активной сложности.

### Что фильтруется при импорте

RaidRU не должен создавать объекты, которых пользователь не видит в оригинальном RaidPlan. Поэтому импортёр отбрасывает:

- `visible: false`;
- `hidden` / helper / mask / viewport / selection объекты;
- элементы с `opacity = 0`;
- элементы с нулевым масштабом;
- внутреннюю геометрию арены, когда используется настоящая фоновая карта RaidPlan;
- неизвестные служебные RaidPlan v2 nodes.

### Линии, стрелки и Path

Начиная с `0.8.35`:

- `line` с `endType: drawn` рисуется как настоящая векторная стрелка;
- обычная `line` рисуется как SVG-линия;
- свободно нарисованный RaidPlan `path` импортируется как stroke-only SVG path;
- `fill` у freehand path больше не замыкает открытую линию в большой белый круг или капсулу;
- если RaidPlan хранит цвет кисти в `fill`, RaidRU использует его как цвет обводки;
- Fabric-трансформации `attr.angle` / `attr.scaleX` / `attr.scaleY` учитываются для линий и составных стрелок, поэтому наклон не теряется при импорте.
- freehand `path` из RaidPlan v2 читается из реального `attr.points`; линия и наконечник сохраняют исходную форму и собираются по `meta.pos / meta.size / meta.scale`;
- вырожденные `path` с одной повторяющейся точкой не импортируются как случайный белый штрих.

## Структура проекта

```text
raidru/
├─ index.html              # точка входа GitHub Pages
├─ app.js                  # интерфейс, состояние, редактор, renderer
├─ raidplan-importer.js    # импорт RaidPlan JSON v2
├─ styles.css              # стили приложения
├─ sw.js                   # service worker и offline/cache assets
├─ manifest.webmanifest    # PWA manifest
├─ icon.svg                # иконка приложения
├─ assets/                 # карты, маркеры, роли, encounter assets
├─ src/                    # Cloudflare Worker
├─ tools/                  # вспомогательные инструменты импорта/отладки
├─ wrangler.toml           # конфигурация Worker
└─ deploy.ps1              # деплой Worker
```

## Локальный запуск

Для статического интерфейса сборщик не требуется. Лучше запускать через локальный HTTP-сервер, чтобы корректно работали service worker и загрузка ресурсов.

Например:

```powershell
python -m http.server 8080
```

После этого открыть:

```text
http://localhost:8080/
```

## Деплой сайта

Основной интерфейс размещён на **GitHub Pages**. Для изменений `app.js`, `index.html`, `raidplan-importer.js`, `styles.css`, `sw.js`, README и ассетов достаточно обычного commit + push в ветку, из которой публикуется Pages.

```powershell
git add app.js index.html raidplan-importer.js sw.js README.md .gitignore
git commit -m "Update RaidRU"
git push
```

Изменение статического сайта **не требует запуска Wrangler**.

## Деплой RaidPlan Worker

Cloudflare Worker нужен только для серверного получения RaidPlan JSON без браузерных CORS-проблем.

Worker требуется передеплоить только при изменениях в `src/`, `wrangler.toml` или самом Worker-коде.

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy.ps1
```

После деплоя health endpoint должен отвечать успешно.

## Кэш и обновление версии

При выпуске новой версии нужно синхронно изменить:

1. видимую версию в `app.js`;
2. query version в `index.html`;
3. query version и имя cache в `sw.js`;
4. `VERSION` и renderer marker в `raidplan-importer.js`;
5. версию в этом `README.md`.

Если после push браузер показывает старую сборку:

```text
Ctrl + F5
```

При необходимости в DevTools → Application можно удалить старый Service Worker / Cache Storage и перезагрузить страницу.

## Проверка RaidPlan после изменений

Перед публикацией импортёра желательно проверять один и тот же эталонный план по сценам.

Минимальная проверка:

- фон совпадает с RaidPlan;
- нет дополнительных зон/масок;
- текст не меняет размер и переносы без причины;
- маркеры и роли находятся в тех же местах;
- NPC и босс сохраняют размер;
- прозрачность фигур совпадает;
- линии и стрелки не превращаются в прямоугольники, круги или капсулы;
- импорт одной сложности не изменяет две другие.

Для синтаксической проверки JavaScript:

```powershell
node --check app.js
node --check raidplan-importer.js
node --check sw.js
```

## Очистка репозитория

В Git не должны попадать локальные кэши и временные файлы:

- `.wrangler/`;
- `*.bak`;
- временные patch-файлы;
- локальные установщики фиксов;
- ZIP-сборки.

Для этого в репозитории используется `.gitignore`.

Если `.wrangler` уже был добавлен в Git раньше, одного `.gitignore` недостаточно. Убрать его только из индекса можно так:

```powershell
git rm -r --cached .wrangler
git commit -m "Stop tracking Wrangler cache"
git push
```

Локальная папка при этом останется на компьютере.

## Данные и приватность

- импортированные сцены RaidPlan сохраняются локально в браузере;
- RaidPlan Worker используется как прокси и не должен сохранять тело пользовательского плана;
- share-ссылка основной стратегии не должна автоматически включать приватную вкладку RaidPlan;
- перед публикацией приватной тактики всегда проверяйте содержимое экспортируемого файла или share URL.

## Источники ресурсов

- RaidPlan.io — карты и исходные планы;
- Warcraft Logs / RPGLogs — replay/mapID и данные для проверки арен;
- игровые/community assets — рейдовые маркеры и визуальные элементы;
- NSRT — таймеры и заметки, используемые в тактических сценариях.

RaidRU не является официальным продуктом Blizzard Entertainment, RaidPlan или Warcraft Logs.

## Текущий фокус разработки

1. точность импорта RaidPlan «объект-в-объект»;
2. отсутствие скрытой/служебной геометрии после импорта;
3. точное соответствие текста, линий, стрелок и составных объектов;
4. стабильная работа разных сложностей;
5. сохранение существующих пользовательских сценариев при обновлениях renderer.
