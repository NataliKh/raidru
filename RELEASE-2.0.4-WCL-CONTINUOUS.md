# RaidRU 2.0.4 — WCL Continuous Import

## Почему появился релиз

В 2.0.3 защита квоты всё ещё могла показать искусственную паузу вроде «Продолжить через 27 мин.», хотя Warcraft Logs сам не возвращал 429. Причиной были два механизма: сохранённый `wcl_budget_guard` backoff и слишком большой фиксированный резерв (`50 points` / порог `0.97`).

## Новая политика

- Строгий таймер создаётся **только после реального HTTP 429 от Warcraft Logs**.
- Старые `wcl_budget_guard` backoff записи 2.0.2/2.0.3 удаляются автоматически при следующем запросе.
- При 90–99% использованной квоты импорт не отключается: Worker уменьшает размер следующей страницы событий.
- Стандартная страница: 10000 событий.
- При высокой загрузке квоты потолок автоматически снижается до 5000 / 2000 / 1000 / 500.
- После первой страницы размер дополнительно адаптируется по реальной стоимости предыдущего WCL-запроса.
- Искусственный резерв уменьшен до 2 points и ~0.2% часовой квоты.
- Если API points действительно практически равны нулю, RaidRU возвращает частичный Replay (если уже есть данные) или честно показывает фактический остаток. Искусственного backoff при этом не создаётся.
- Checkpoint/page cache сохраняются.
- Реальный 429 по-прежнему не ретраится автоматически.

## Важно

Этот релиз не пытается обходить rate limit WCL. Он убирает только собственную чрезмерно консервативную блокировку RaidRU и использует оставшийся разрешённый бюджет аккуратнее.
