# RaidRU 2.0.3 — WCL Adaptive Import

## Зачем этот релиз

В 2.0.2 защита WCL была слишком консервативной: `70%` использованной часовой квоты считались причиной полностью остановить импорт. Это защищало от 429, но делало прямую вставку WCL-ссылки непригодной в обычной работе.

2.0.3 меняет принцип: **деградация качества вместо отказа от работы**.

## Новый обычный режим

`/wcl/replay?mode=smart` и `mode=fast` используют выборку `dataType: Casts` вместе с `includeResources: true`.

Для RaidRU этого достаточно, чтобы получить:

- координаты источников/целей на кастах;
- `nextX/nextY`, когда WCL их отдаёт;
- касты босса;
- mapID;
- временную ось.

Игроки постоянно используют способности, поэтому выборка кастов даёт практический movement sample без загрузки полного боевого event stream.

## Квота

Новые значения по умолчанию:

```toml
WCL_SOFT_LIMIT = "0.85"
WCL_HARD_LIMIT = "0.97"
WCL_MIN_RESERVE = "50"
WCL_MAX_PAGES_PER_REQUEST = "16"
WCL_EVENT_PAGE_LIMIT = "10000"
```

`WCL_SOFT_LIMIT` больше не останавливает импорт. Остановка возможна только у hard threshold или когда прогноз следующей страницы не помещается в остаток + резерв.

Старый `wcl_budget_guard` backoff из 2.0.2 не считается жёсткой блокировкой: после обновления Worker перепроверяет текущую квоту и, если fast page безопасна, продолжает загрузку сразу.

Реальный WCL HTTP 429 остаётся строгим backoff и не ретраится автоматически.

## Partial Replay

Если Worker уже успел получить полезные координаты/касты, но следующая страница стала небезопасной, ответ имеет HTTP `206` и содержит обычный Replay payload с:

```json
{
  "partial": true,
  "quality": "partial",
  "resumeAfter": 1234
}
```

Клиент сразу открывает этот Replay. Пользователь может:

- смотреть движение;
- создавать WCL-черновик;
- экспортировать Replay;
- вернуться позже и догрузить оставшуюся часть с checkpoint.

## Высокая точность

После успешного fast replay интерфейс показывает необязательную кнопку **«Высокая точность»**. Она запрашивает полный event stream (`mode=full`) и предназначена для случаев, когда действительно нужна максимальная плотность координат.

Fast replay — основной продуктовый режим.

## Кэш

- завершённые 2.0.2 Replay переиспользуются без WCL запросов;
- новые page cache keys учитывают режим (`casts`/`all`);
- старый незавершённый checkpoint 2.0.2 можно продолжить fast-выборкой с текущего cursor;
- финальные 2.0.3 cache keys разделены по fast/full.

## Проверки

`test-wcl-safe-worker.mjs` проверяет:

1. checkpoint между Worker batches;
2. `dataType: Casts`;
3. page limit 10000;
4. использование WCL при 75% quota;
5. hard stop у 98%;
6. HTTP 206 partial replay после уже полученной страницы;
7. отсутствие retry-loop после настоящего 429;
8. final replay cache.
