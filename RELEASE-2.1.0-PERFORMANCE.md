# RaidRU 2.1.0 — Performance Core

Цель релиза: ускорить RaidRU после появления WCL Replay, Mechanics Analysis и Workspace, не меняя RaidPlan renderer и WCL Worker API.

## Основные причины тормозов, которые устранены

1. `positionAt()` на каждом кадре Replay фильтровал **весь массив координат** отдельно для каждого игрока.
2. `replayBounds()` повторно проходил все координаты при расчёте каждой позиции.
3. Replay пересоздавал DOM всех игроков через `innerHTML` на каждом animation frame.
4. Replay обновлялся до 60 раз/с, хотя визуально для тактической карты достаточно ~30 FPS.
5. `save()` сериализовал весь глобальный `state` в `localStorage` на каждом `pointermove`/`input`; туда же попадал огромный Replay.
6. Mechanics Analysis повторно пересчитывал группы механик и движение рейда при каждом фильтре/раскрытии карточки.
7. Service Worker при установке заранее скачивал почти всю палитру и карты и использовал network-first даже для статических изображений.
8. В проекте лежала неиспользуемая дублирующая папка `assets/palette/encounter/raidplan` (55 файлов, идентичных `game`). В чистой full-сборке она удалена.

## Что изменено

### Replay

- Индекс `positionsByActor` строится один раз и хранится в `WeakMap`.
- Поиск позиции игрока использует бинарный поиск.
- Bounds карты кешируются один раз на Replay.
- Поиск ближайшего события использует бинарный поиск.
- DOM игроков создаётся только при изменении набора игроков; на кадрах меняются только координаты.
- Визуальное обновление ограничено примерно 30 FPS.

### Persistence / Workspace

- Полный `replay.data` больше не записывается в `localStorage`.
- Сохраняются URL, источник, mapID и калибровка, поэтому бой можно повторно открыть из серверного WCL cache.
- `save()` теперь debounce ~320 ms вместо синхронного `JSON.stringify` на каждом движении мыши.
- `pagehide` / скрытие вкладки принудительно сбрасывают ожидающее сохранение.
- Workspace использует общий оптимизированный writer.
- При первом запуске 2.1.0 старый огромный Replay автоматически вычищается из `localStorage`, не удаляясь из текущей памяти.

### Mechanics Analysis

- кешируются расчёты `movement209()`;
- кешируется список сильных перемещений;
- кешируется группировка mechanics pack;
- кешируется список occurrences;
- полный Browser JSON не пересобирается заново при каждом UI-клике.

### Service Worker / assets

- precache уменьшен до app shell (~0.64 MB вместо загрузки всей палитры/карт);
- изображения и `/assets/` теперь cache-first и подгружаются лениво;
- JS/CSS/HTML остаются network-first для корректного обновления;
- clean full build не содержит неиспользуемую копию `assets/palette/encounter/raidplan`.

### Rendering

- карточки Mechanics Analysis используют `content-visibility:auto`, поэтому браузер не обязан полностью рисовать длинный список за пределами экрана.

## Локальный benchmark на реальном Replay

Файл: `ZHMFmALfbdkaz7WX-fight-last.raidru-replay.json`, 42 708 координатных точек.

1600 запросов позиции (20 игроков × 80 временных точек):

- старый поиск через `positions.filter(...)`: ~1052 ms;
- новый индекс + binary search: ~1.27 ms;
- ускорение в изолированном тесте: ~830×.

Пример сериализации состояния с Replay на тех же данных:

- старый JSON: ~14.29 MB, ~85.6 ms на один `JSON.stringify`;
- новый persistent JSON без `replay.data`: ~0.6 KB в тестовой модели, ~0.13 ms;
- ключевой эффект в приложении: сериализация больше не происходит на каждом `pointermove`.

Цифры benchmark зависят от компьютера и используются как regression-сигнал, а не как обещание точного FPS.

## Совместимость

Не изменялись:

- `src/index.js` / Cloudflare Worker;
- WCL endpoint contract;
- RaidPlan importer/renderer;
- форматы планов;
- WCL coordinate calibration 2.0.7;
- Mechanics API 2.0.10.

Worker для 2.1.0 повторно деплоить не требуется.
